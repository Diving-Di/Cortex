# M4 正式版增强决策与验证

## 定时报告

- 后端每 60 秒使用独立迁移/调度角色原子领取到期任务，`FOR UPDATE SKIP LOCKED` 防止多实例重复领取。
- 实际读取、生成和写入仍切换到任务所属租户的 `TenantContext`，并受 FORCE RLS 保护。
- 支持日、周、月任务，IANA 时区，启用/禁用、立即重试，以及最近 50 次结果。
- 自动生成若覆盖已有周期报告，会先创建历史版本；没有来源或 AI 未配置时记录失败，不生成虚构报告。
- 可用 `SCHEDULED_REPORTS_ENABLED=false` 禁用内置调度器，轮询间隔由
  `SCHEDULED_REPORT_POLL_SECONDS` 调整。

## DL-303 长时间运行与资源泄漏验证

2026-07-23 已对发布候选版本完成 59.1 分钟 Docker soak test：

- 共 53 组容器采样，时间范围为 15:45:36 至 16:44:42。
- 后端内存从 76.23 MiB 到 76.42 MiB，变化 +0.19 MiB，完整范围 75.92–76.82 MiB。
- 后端 PID 全程为 8；PostgreSQL PID 全程为 7；前端 PID 全程为 21。
- PostgreSQL 内存从 38.81 MiB 到 39.11 MiB，变化 +0.30 MiB。
- 所有容器最终仍在运行，后端健康状态为 `healthy`，内部 `/readyz` 返回数据库正常。
- 后端日志未发现 OOM、Traceback、连接池耗尽或定时调度异常。
- Windows 主机端健康采样后半段超时；容器内部健康检查持续成功，定位为 Docker Desktop
  端口转发故障，不计为应用服务失效。

结论：一小时观察窗口内无持续线性内存增长、PID 增长或连接泄漏，DL-303 验收通过。
生产发布后仍建议执行 24 小时以上观察，以覆盖低频任务和跨日调度。

## DL-304 语义向量检索决策

当前不引入。现有 `pg_trgm`、日期、类型和标签组合检索已覆盖 MVP，向量检索会增加嵌入模型、
重建索引、备份兼容和离线可用性的成本。触发重新评估的条件：真实回忆问答样本中关键词检索
Top-8 召回率低于 85%，且同义表达是主要失败原因。届时优先评估 PostgreSQL `pgvector`，
不先引入独立向量数据库。

## DL-306 Web 自动部署决策

当前不建设自动生产部署。保留现有 Docker Compose、健康检查、迁移和发布验收流程，避免在没有
明确托管平台、密钥管理与回滚策略前绑定 CI/CD。触发条件：确定生产托管平台，且人工发布频率
达到每月两次以上。届时流水线必须包含构建、测试、镜像签名、数据库备份、迁移、健康检查和
失败自动回滚。
