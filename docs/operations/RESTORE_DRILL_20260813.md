# 2026-08-13 联合恢复演练

使用当前数据库与 `app_data` 的一致引用快照，在随机命名的新 network、PostgreSQL volume、应用 volume 和后端容器中恢复。
演练没有覆盖、删除或挂载写入当前 `cortex` volume，也没有在报告中保存文件名、正文、邮箱或密钥。

| 项目 | 实测结果 |
| --- | ---: |
| 备份数据库 | 16,178,309 bytes |
| 备份应用数据 | 111,922,780 bytes |
| 备份耗时 | 81.684 s |
| 数据库恢复 | 10.924 s |
| 应用数据恢复 | 8.866 s |
| 迁移 | 1.077 s，已是 version 31，无待执行迁移 |
| 一致性校验 | 2.718 s |
| non-AI smoke | 71.866 s |
| 实测 RTO | 103.313 s |
| 观测 RPO | 61 s |

校验通过：55 张 public 表、migration 31、45 张 RLS 且 FORCE RLS 表、`cortex_app` 低权限连接、
DB→文件缺失 0、文件→DB 孤儿 0，以及注册/登录/Token/租户隔离/附件/导出/软删除 smoke。

演练同时发现源卷有 85 个 knowledge 和 2 个 research 历史孤儿（合计约 1.63 MiB）。未删除这些用户数据；
备份脚本只归档数据库当前引用且存在的业务文件，因此恢复包保持双向一致。该观测 RPO/RTO 仅代表此次本机、
当前数据量和已缓存镜像环境，不能作为生产 SLA。
